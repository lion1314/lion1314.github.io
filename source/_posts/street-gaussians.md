把一段车载相机拍到的街景，变成可以任意换视角、还能把车单独拎出来挪走的三维场景，需要多久？这篇论文给的答案是：**单张 4090 训练 30 分钟，渲染 135 FPS @ 1066×1600**，而且画质把当时的 NeRF 类 SOTA 甩开一截（PSNR +12.1%）。

<!-- more -->

## 一句话总结

用一组**显式 3D 高斯点云**分别表示静态背景和每一辆运动车辆，配合**可优化的跟踪位姿**（把物体从局部坐标系变换到世界系）和 **4D 球谐动态外观模型**（用傅里叶系数编码时间变化的外观），从而绕开 NeRF 的 raymarching，换来实时渲染、实例级分解和场景编辑能力。

## 1. 为什么动态街景难

自动驾驶仿真需要「真实感 + 可交互 + 实时」三者兼得，已有路线各有硬伤：

| 路线 | 代表工作 | 卡在哪 |
| --- | --- | --- |
| 静态大场景 NeRF | Block-NeRF、GridNeRF、DNMP、NeuRas | 训练慢，且**不能处理动态车辆** |
| 组合式动态神经场 | Panoptic Neural Fields、NSG、UniSim、MARS、EmerNeRF | 用跟踪位姿把观测映射到 canonical 空间再用 NeRF 建模，画质尚可但**训练成本高、渲染慢**（0.2–0.7 FPS） |
| 4D 动态场（不区分实例） | K-Planes、NeRFPlayer、HyperNeRF、SUDS | 不是实例级表示，仿真里没法单独操作一辆车 |
| 3D Gaussian Splatting | 3DGS [19] | 高质量实时渲染，但**假设场景静止** |
| 传统仿真引擎 | CARLA、AirSim | 人工建模成本高、真实感不足 |

论文同期的并发工作 DrivingGaussian [79]、PVG [8] 也在把 3DGS 搬进街景，但表示方式不同。Street Gaussians 的切入点很直接：**把动态场景拆成「静态背景 + N 个刚性运动车辆」，全部改用显式点云表示**。

## 2. 方法：场景表示

整体流水线（论文 Fig.2）：

```text
输入图像序列 + LiDAR + 跟踪框
        │
        ▼
场景表示：背景点云（世界系） + N 个物体点云（物体局部系）
        │   几何模型：位置 / 不透明度 / 旋转 / 缩放
        │   外观模型：背景 SH，前景 4D SH（傅里叶系数）
        ▼
渲染时刻 t：恢复外观系数 ──► 按跟踪位姿变换物体 ──► 拼接所有点云
        ▼
EWA 投影到 2D ──► α 混合 ──► 叠加天空 cubemap
        ▼
图像 / 深度图 / 语义图（同时支持分解与编辑）
```

![Fig.2 Street Gaussians 整体架构](/images/street-gaussians/fig02-overview.png)

<p class="fig-caption">论文 Fig.2：背景点云与每个物体点云各自挂几何模型与外观模型；物体模型带可优化跟踪框，经过 Composition 拼接后由 Point-based Rendering 输出图像、分解结果与语义图。</p>

### 2.1 背景模型：世界坐标系下的一组 3D 高斯

每个背景点挂这些可学习属性：

- 位置 `µ_b ∈ R³`、不透明度 `α_b ∈ R`
- 协方差 `Σ_b`：不直接优化矩阵，而是拆成缩放矩阵 `S_b`（对角元素）和旋转矩阵 `R_b`（单位四元数），避免优化过程产生非法协方差

```text
Eq.1    Σ_b = R_b · S_b · S_bᵀ · R_bᵀ
```

- 球谐系数 `z = (z_{m,l})`：与视线方向投影出的 SH 基函数相乘，得到视角相关颜色
- 语义 logits `β_b ∈ Rᴹ`（M 为语义类别数）：让渲染器可以直接输出语义图

### 2.2 物体模型：局部坐标系 + 跟踪位姿

每辆车拥有自己的点云，属性含义与背景相同（`α`、`S` 一致），但**位置 `µ_o` 和旋转 `R_o` 定义在物体局部坐标系**。跟踪器给出每帧的旋转 `R_t` 与平移 `T_t`（共 `N_t` 帧），变换到世界系：

```text
Eq.2    µ_w = R_t · µ_o + T_t
        R_w = R_t · R_o
```

再把 `R_w`、`S_o` 代回 Eq.1 得到世界系协方差 `Σ_w`。

语义表示上有个细节：物体的语义不是 M 维向量，而是**一维可学习标量 `β_o`**（跟踪器给出的车辆类别），渲染时转成 M 维 one-hot 再与背景的 `β_b` 融合。

论文明确提到，现成跟踪器给出的框通常带噪声，直接用会拉低画质——这是 2.5 节「位姿优化」的动机。

### 2.3 4D 球谐：把时间编码进外观

**为什么需要它**：车在场景里移动时，车身外观会受它在全局场景中的位置与环境光照影响（比如车身阴影随位置变化），静态 SH 表达不了。最笨的办法是每个时刻存一份 SH，但存储会爆炸。

**做法**：把每个 SH 系数 `z_{m,l}` 换成一组傅里叶系数 `f_i ∈ Rᵏ`，给定时刻 `t` 用实值逆离散傅里叶变换恢复：

```text
Eq.3    z_{m,l}(t) = Σ_{i=0}^{k-1} f_i · cos(i π t / N_t)
```

`k = 5`（附录 A：平衡性能与存储）。论文 Fig.3 的对比很直观：去掉 4D SH 后，车身阴影区域出现明显噪声与伪影；消融里运动物体 PSNR* 从 30.23 掉到 29.27。

![Fig.3 4D 球谐模型的效果对比](/images/street-gaussians/fig03-4d-sh.png)

<p class="fig-caption">论文 Fig.3：上排是不同时刻的输入序列，车身外观随位置与光照变化；下排对比「有 / 无 4D SH」与真值，去掉 4D SH 后车身出现明显噪声伪影。</p>

### 2.4 点云初始化：LiDAR 与 SfM 必须融合

3DGS 默认用 SfM 点云，但街景里大量欠观测、无纹理区域会让 SfM 失效。本文改用**自车采集的聚合 LiDAR 点云**做初始化，颜色通过投影到图像平面查像素值获得。

| 部分 | 初始化策略 |
| --- | --- |
| 物体 | 收集 3D 框内的聚合点，变换到局部系；LiDAR 点少于 2K 的物体，改为在框内随机采 8K 点 |
| 背景 | 剩余点云体素下采样（0.15 m），滤除训练相机不可见的点 |
| 补充 | 融合 SfM 点云补偿 LiDAR 在远处、大范围的覆盖不足；SfM 在已知相机位姿下三角化得到，特征提取时用 mask 忽略动态物体 |

两者同在世界系，可以直接拼接。附录 Table 6 给出了很有说服力的证据：

| 变体 | PSNR | SSIM | LPIPS |
| --- | --- | --- | --- |
| 完整模型 | 32.63 | 0.928 | 0.083 |
| 去掉 LiDAR | 30.72 | 0.920 | 0.100 |
| 去掉 SfM | 29.97 | 0.911 | 0.106 |
| 去掉天空建模 | 31.12 | 0.921 | 0.100 |

**去掉 SfM 比去掉 LiDAR 更差**——LiDAR 管近处纹理细节（路面），SfM 管远处覆盖（对面的树、远处路牌），缺一不可。

## 3. 方法：渲染

给定渲染时刻 `t`，渲染是一次「拼接 + 光栅化」，没有 raymarching：

1. 用 Eq.3 恢复各高斯的 SH 系数，算出颜色
2. 用 Eq.2 按 `(R_t, T_t)` 把物体点云变换到世界系
3. 拼接背景点云与所有变换后的物体点云
4. EWA splatting 投影到 2D（相机外参 `W`、内参 `K`，`J` 为 `W` 的雅可比）：

```text
Eq.4    µ′ = K W µ
        Σ′ = J W Σ Wᵀ Jᵀ
```

5. 逐像素 α 混合：

```text
Eq.5    C = Σ_i c_i · α_i · Π_{j<i} (1 − α_j)
```

其中 `α_i` 是不透明度乘以 2D 高斯概率，`c_i` 是 SH 得到的颜色。

6. **天空单独处理**：3D 高斯定义在欧氏空间，不适合建模天空这类无穷远景，所以用一个高分辨率 cubemap 把视线方向映射为天空颜色 `C_sky`：

```text
Eq.8    C = C_g + (1 − O_g) · C_sky
```

`O_g` 是高斯部分的累积不透明度。cubemap 分辨率 1024，不损失推理速度。

7. 把 Eq.5 里的 `c_i` 换成深度、不透明度、语义 logits `β`，就能顺带渲染深度图、不透明度图和语义图——几乎零额外成本。

> 显式表示最实用的收益就在这里：所有模型拼成一个点云后一次光栅化，前后景分解、编辑、多通道输出都是同一个渲染过程的副产品。

## 4. 方法：训练

### 4.1 跟踪位姿当成可学习参数

跟踪器输出有噪声，本文给每个变换矩阵加一个可学习残差：

```text
Eq.6    R′_t = R_t · ∆R_t
        T′_t = T_t + ∆T_t
```

- `∆T_t` 就是一个 3D 向量；`∆R_t` 由**偏航角偏移 `∆θ_t`** 转成旋转矩阵（只放开 yaw，不让旋转自由漂移）
- 梯度可以直接回传，不需要隐式函数或中间过程，反向传播不增加额外计算

这是全文我认为最值得借鉴的一处设计：**用残差参数化纠正传感器/跟踪噪声，而不是整体自由优化位姿**。

### 4.2 损失函数

```text
Eq.7 / Eq.9    L = L_color + λ₁ L_depth + λ₂ L_sky + λ₃ L_sem + λ₄ L_reg
```

| 损失项 | 形式 | 权重 | 关键细节 |
| --- | --- | --- | --- |
| `L_color` | `(1−λ_SSIM)·L1 + λ_SSIM·D-SSIM` | `λ_SSIM = 0.2` | 沿用 3DGS 的图像重建损失 |
| `L_depth` | L1（渲染深度 vs LiDAR 投影深度） | `λ₁ = 0.01` | **只回传深度误差最小的 95% 像素**，抑制噪点观测（借鉴 UniSim [71]） |
| `L_sky` | 二元交叉熵（渲染不透明度 `O_g` vs 天空 mask） | `λ₂ = 0.05` | mask 由 Grounding DINO 输入文本 "sky" 出框，再喂给 SAM 生成 |
| `L_sem` | 逐像素 softmax 交叉熵 | `λ₃ = 0.1` | 监督来自 Video K-Net 的 2D 语义预测；**只对语义 logits β 回传**，避免噪声标签污染几何（依据 [49]） |
| `L_reg` | 前景物体累积不透明度 `O_obj` 的熵损失 | `λ₄ = 0.1` | 在自适应密度控制**之后**才加入，专门去除车辆周围的 ghosting、强化前后景分解 |

### 4.3 实现细节与超参

| 项 | 值 |
| --- | --- |
| 迭代 / 优化器 | 30,000 / Adam，沿用 3DGS 配置 |
| 硬件 | 单张 RTX 4090 |
| `∆T` 学习率 | `5e−3 → 5e−5`（指数衰减） |
| `∆R` 学习率 | `1e−3 → 1e−5`（指数衰减） |
| 天空 cubemap | 1024，lr `1e−2 → 1e−4` |
| 傅里叶系数 `k` | 5 |
| SH 阶数 | **降到 1**（3DGS 默认 3），因为街景视角相关效应弱，降阶防过拟合 |
| LiDAR 体素 | 0.15 m |
| 背景 / 物体尺度 | 背景固定 20 m；物体由 3D 框尺寸决定 |
| 前景剪枝 | 对每个物体模型采样点作为概率分布，把采样点落在框外的高斯剪掉，防止物体高斯长到被遮挡区域 |

## 5. 实验

### 5.1 设置

- **Waymo Open**：挑 8 个「运动物体多、自车运动明显、光照复杂」的序列，每条约 100 帧；每第 4 帧作测试，其余训练；因基线在高分辨率下内存吃紧，图像降采样到 **1066×1600**；检测框用 CASA [62] + 3D MOT [63] 生成。
- **KITTI / Virtual KITTI2**：沿用 MARS [64] 的设置，分辨率 **375×1242**，按 75% / 50% / 25% 三种训练数据量划分；用 KITTI 官方 tracklets。
- **基线**：NSG、MARS、3D GS、EmerNeRF。其中 NSG 与 MARS 用 **GT tracklets** 训练评估（对本文并不占优的条件）。
- **指标**：PSNR / SSIM / LPIPS，外加 **PSNR\***——把 3D 框投影到 2D（长宽各扩 1.5 倍确保覆盖），只在框内像素算 MSE，专门测运动物体；所有方法用同一 tracklet mask 保证公平。

### 5.2 Waymo 主结果（Table 1）

| 方法 | PSNR↑ | SSIM↑ | LPIPS↓ | PSNR\*↑ | FPS↑ |
| --- | --- | --- | --- | --- | --- |
| 3D GS | 29.64 | 0.918 | 0.117 | 21.25 | 205 |
| NSG | 28.31 | 0.862 | 0.346 | 24.32 | 0.47 |
| MARS | 29.75 | 0.886 | 0.264 | 26.54 | 0.68 |
| EmerNeRF | 30.87 | 0.905 | 0.133 | 21.67 | 0.21 |
| **Ours** | **34.61** | **0.938** | **0.079** | **30.23** | **135** |

几个要点：

- PSNR 相对最强基线 +12.1%，PSNR\* +13.9%，LPIPS 几乎减半（0.133 → 0.079）。
- **3D GS 的 205 FPS 更快，但它只能处理静态场景**，运动物体区域 PSNR\* 只有 21.25，比本文低 9 dB。
- 训练/渲染成本对比（Fig.1）：本文 30 min / 135 FPS；EmerNeRF 2.5 h / 0.21 FPS；MARS >18 h / 0.68 FPS。
- 定性结果（Fig.4）：NSG、MARS 模糊畸变；3D GS 与 EmerNeRF 在运动物体区域出 ghosting；本文细节清晰。

![Fig.4 Waymo 数据集上的定性对比](/images/street-gaussians/fig04-waymo-qualitative.png)

### 5.4 消融（Table 3，Waymo 全序列平均）

| 变体 | PSNR↑ | PSNR\*↑ | SSIM↑ | LPIPS↓ |
| --- | --- | --- | --- | --- |
| w/o LiDAR | 34.02 | 29.53 | 0.934 | 0.087 |
| w/o 4D SH | 34.36 | 29.27 | 0.937 | 0.081 |
| w/o pose opt. | 34.18 | 28.24 | 0.935 | 0.081 |
| w/ GT pose | 34.61 | 29.84 | 0.937 | 0.080 |
| **完整模型** | **34.61** | **30.23** | **0.938** | **0.079** |

三个结论：

1. **位姿优化贡献最大**：去掉后 PSNR\* 从 30.23 掉到 28.24（−1.99 dB）。更有意思的是**完整模型甚至超过用 GT 位姿训练的版本**（30.23 vs 29.84），论文给的解释是 GT 标注本身也带噪声。
2. **4D SH 主要服务运动物体**：PSNR 只掉 0.25，PSNR\* 掉 0.96，与「外观随位置/光照变化」的动机一致。
3. **LiDAR 初始化对整体和前景都有收益**，但即使完全不用 LiDAR，仍显著优于所有基线。

附录 Table 5 把第 1 点讲得更透（PSNR\*，两个序列）：

| 方法 | 不优化位姿 | 优化位姿 | GT 位姿 |
| --- | --- | --- | --- |
| MARS（隐式），序列 A | 25.78 | 27.68 | 29.74 |
| **Ours**，序列 A | 29.08 | **31.35** | 30.84 |
| MARS（隐式），序列 B | 24.38 | 25.83 | 26.94 |
| **Ours**，序列 B | 25.86 | **27.98** | 28.02 |

同样是「加位姿优化」，隐式表示（MARS）提升后仍够不到 GT 位姿，显式表示却能追平甚至反超。论文归因于**显式表示里位姿梯度传播更高效**——我认为这是全文最值得记住的一句话。

### 5.5 应用

- **场景编辑**（Fig.7）：实例级表示天然支持旋转车辆朝向、平移车辆、把一辆车替换成另一辆。
- **物体分解**（Fig.8 / Fig.16）：NSG 无法干净分离前景，MARS 背景出 floaters；本文分解干净且高保真，`L_reg` 熵损失显著去除车辆周围鬼影（Fig.11）。
- **语义分割**（Fig.9 / Table 4，KITTI，mIoU）：Video K-Net 直接跑真值图 57.94，跑本文渲染图 53.81，而**本文自己渲染的 3D 语义场 58.81**。3D 语义融合在阴影等歧义区域比逐帧 2D 预测更稳。
- **外推**（Fig.14）：相机平移 2 m 模拟变道视角，仍能渲染出高质量结果。

## 6. 局限：原文承认的与我的补充

### 论文作者自述（附录 C）

1. **只支持刚性动态场景**（静态街景 + 运动车辆），行人等非刚性运动物体处理不了；作者指向 4D Gaussian Splatting [73] 作为可能的扩展。
2. **依赖跟踪器召回率**：漏检的车辆无法靠位姿优化补回来；用 2D 跟踪补连续 tracklet 可以缓解，「无 tracklet 的街景建模」仍是开放问题。
3. **仍需逐场景优化**：前馈式预测通用 3D 高斯被列为未来工作。

### 我的补充（个人观点，非论文原文）

- **天空 cubemap 是工程补丁而非表示创新**：它解决的是「欧氏空间高斯无法表达无穷远」，代价是引入一套独立的 mask 生成链路（Grounding DINO + SAM）和额外超参。这提醒我们：3DGS 类方法在无界场景里普遍需要远景兜底。
- **评测设置对基线并不宽松也不苛刻**：Waymo 降采样到 1066×1600 是因为基线内存不够，PSNR\* 用扩展 1.5 倍的框内像素，框本身来自跟踪器——指标与跟踪质量有耦合。
- **语义能力是「2D 教师蒸馏进 3D」**：58.81 的 mIoU 依赖 Video K-Net 的预测质量，不是从图像自监督学出来的语义。
- **时间是 2024 年的横截面**：DrivingGaussian、PVG 只是作为并发工作提及，没有与后续方法（如各类 feed-forward 3DGS、端到端重建）比较。看数字时记得标定时间点。
- **仍需 LiDAR**：虽然消融显示不用 LiDAR 也强于基线，但「LiDAR + 已知相机位姿 + 跟踪框」这套输入在纯视觉量产场景里并不便宜。

## 7. 与 3DGS / 神经重建训练实践的关联

> **这一节是个人分析，不是论文原文观点**，结合我自己做 3DGS / 3DGUT 神经重建训练时关心的初始化、深度监督、位姿噪声等问题。

1. **双源初始化可以直接抄**：论文用 Table 6 明确验证了「聚合 LiDAR + SfM 互补，缺一个都明显掉点」，还给了体素 0.15 m、物体框内点不足 2K 时随机采 8K 的兜底。调初始化策略时，这比凭感觉试靠谱得多。
2. **深度监督的防噪技巧很便宜**：L1 深度损失只回传误差最小的 95% 像素，几乎零成本就能抑制 LiDAR 噪点与标定误差带来的错误梯度。做 depth 监督时值得先加这一层。
3. **位姿/标定误差用残差参数化**：`R′ = R·∆R`、`T′ = T+∆T`，且 `∆R` 只放开 yaw。比起整体自由优化，这种受限残差既纠正噪声又不破坏结构，对存在标定偏差的自采数据尤其适用。
4. **SH 阶数别默认照抄 3DGS**：街景把 SH 从 3 降到 1 防过拟合。如果近景模糊同时伴随视图相关伪影，先查 SH 阶数是不是开太高了。
5. **前景剪枝 = 给高斯加软边界**：把物体框外采样到的高斯剪掉，防止它长进遮挡区。这与「约束 Gaussian 不越过 LiDAR 观测边界」是同一类思路。
6. **本文没覆盖、但我正在调的**：normal 监督、near-depth bound、单目深度（DepthAnythingV2）软监督，这篇论文里都没有。可以把 Street Gaussians 当作一条**「LiDAR 硬几何约束基线」**：先用 LiDAR 初始化 + LiDAR 深度损失把几何打牢，再逐项叠加软监督；度量上借鉴 PSNR\* 的思路，单独统计近景/运动区域，别只看全图平均 PSNR（全图 PSNR 对 4D SH、位姿优化这些改动并不敏感，Table 3 里 PSNR 几乎不动，PSNR\* 却掉近 2 dB）。

## 10. 三句话备忘

1. **表示**：背景 + 每辆车各自一组 3D 高斯，物体几何定义在局部系，靠跟踪位姿变换到世界系，渲染时拼接后一次光栅化。
2. **两个关键补丁**：4D 球谐（傅里叶系数编码时变外观，k=5）与位姿残差优化（只放开 yaw + 平移）；后者让「普通跟踪器位姿」达到甚至超过 GT 位姿。
3. **工程上最值得记的**：LiDAR + SfM 双源初始化必须融合，深度损失只回传误差最小的 95% 像素，SH 阶数降到 1，前景高斯框外剪枝。
